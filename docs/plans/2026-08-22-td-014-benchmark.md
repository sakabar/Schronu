# TD-014 Single-cell Sync Benchmark Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Measure the real Google Sheets cost of the existing single-cell synchronization path before choosing a TD-014 optimization.

**Architecture:** Keep the simple `onEdit` trigger and synchronization behavior unchanged. Add local characterization tests and one structured timing record per qualifying edit, then use Apps Script execution duration as the end-to-end measurement and the timing record to identify expensive stages.

**Tech Stack:** Google Apps Script V8, Node.js 24 built-in test runner, Rust/Cargo quality gates

---

## Contracts

- Do not introduce the Sheets Advanced Service or an installable trigger during measurement.
- Do not log task IDs, edited values, synchronized values, or other task content.
- Emit one JSON record for a qualifying synchronization edit. Non-target sheets, header-only edits, non-sync columns, and command-output paste remain unlogged and unchanged.
- Preserve existing behavior for lock failure, empty task ID, missing target task, and missing target sheet while recording an outcome when the event reached synchronization handling.
- Do not call `SpreadsheetApp.flush()`. Apps Script execution duration is the authoritative end-to-end value; individual write timing measures only the `setValue` call.

## Timing schema

Each qualifying edit writes one JSON object with these fields:

- `event`: fixed to `td_014_single_cell_sync`
- `outcome`: `synced`, `lock_unavailable`, `source_task_id_empty`, `target_task_not_found`, or `target_sheet_missing`
- `sourceSheet` and `targetSheet`: configured sheet names only
- `rowsScanned`: number of target task-ID rows loaded
- `lockWaitMs`
- `sourceTaskIdReadMs`
- `targetLastRowReadMs`
- `targetIdReadMs`
- `targetIdSearchMs`
- `sourceValueReadMs`
- `targetValueWriteCallMs`

Every duration is a non-negative integer. Stages not reached are recorded as zero.

## Real Spreadsheet protocol

1. Copy the production-like Spreadsheet so it retains approximately 1,000 rows and 50-100 task IDs on both configured sheets.
2. Deploy the measured `apps_script/main.js` to the copied bound script.
3. Use only N or R for measurement; do not overwrite formulas in L or P.
4. Select matching task IDs near the start, middle, and end of the target ID list.
5. Perform ten one-cell edits for each search position, split evenly between both synchronization directions, for 30 samples total.
6. Record the first execution separately as the cold sample. Calculate median, p95, maximum, and failure count from the remaining samples.
7. Use Apps Script execution duration as end-to-end latency and JSON timing fields only for stage diagnosis.

## Decision thresholds

- Median below 500 ms, p95 below 1 second, zero failures: retain the current lookup and re-plan TD-014 around correctness.
- Median 500 ms to 1 second, or p95 1-2 seconds: plan a small optimization while retaining the simple trigger.
- Median above 1 second, p95 above 2 seconds, or any missed synchronization: reconsider an installable trigger and Sheets batch API.
- If median `targetIdReadMs` is at least 50% of end-to-end median, optimize the ID-column read first.
