# Apps Script 外部設計

このディレクトリの `main.js` は、Schronu の出力を貼り付けて使う Google Spreadsheet 向けの補助スクリプトです。

## 対象シート

対象シートは以下の2つです。

- `実ログ`
- `優先度低い順`

両シートは、同じexport snapshotのタスク集合を異なる順序で表示する用途を想定しています。A列の`ind`とB列の`task_id`を組み合わせ、同じ予定segmentを対応付けます。B列の`task_id`だけを使う同期は、同一タスク全体を対象とする場合に限ります。

## 列仕様

| 列 | 用途 |
| --- | --- |
| A | `ind`。同じexport snapshot内でB列と組み合わせるsegment識別子 |
| B | `task_id`。A列とのsegment複合key、およびtask単位同期のキー |
| L | 開始時刻。相手シートの対応segmentだけへ同期 |
| N | 完了フラグ。両シートの同一task全segmentへ同期 |
| P | 完了時刻。相手シートの対応segmentだけへ同期 |
| Q | 抽出対象。`shell/copy_for_spreadsheet.sh` ではP列が手入力のときTRUEになる式を入れる |
| R | 両シートの同一task全segmentへ同期。初期値は空白、`W`と`d`はコマンド生成指定、`t`はSpreadsheet上の表示制御用 |
| S | 実作業時間。`generate_command_from_spreadsheet.sh`が`働`コマンドの分数へ変換する |

データ行は3行目から始まる前提です。

完全なA-S列の定義はリポジトリルートの`spreadsheet_columns.tsv`を正本とします。A-J列はSchronu出力、K-S列はSpreadsheetの補助列です。

## 論理日境界の睡眠時間

`shell/copy_for_spreadsheet.sh`は06:00を論理日の境界とします。00:00から05:59開始のタスクは前の論理日に属します。入力内で新しい論理日へ移った最初のタスクは、G列の見積もり分数を変更せず、P列の予定完了時刻へ420分を加算し、N列へ`F`を設定します。N列が`F`の行は、Spreadsheetから戻す際に`終`コマンドが生成されません。コピー対象の先頭行と、R列が`W`または`d`の行には加算しません。

## 起動時の動作

Google Sheets を開くと、メニューに `ユーザー関数` が追加されます。

メニュー項目は以下です。

- `時刻形式を再適用`

また、起動時にも時刻形式の再適用を実行します。

## 時刻形式の再適用

`優先度低い順`の以下の範囲に、時刻表示形式`hh:mm`を設定します。

- `L3:M500`
- `O3:P500`

`実ログ`は、`generate_command_from_spreadsheet.sh`へ完了日付も渡せるように時刻形式を上書きしません。

対象シートが存在しない場合は、存在しないシート名をアラートで表示します。

## 編集時の同期

`実ログ`または`優先度低い順`の3行目以降でL/P列を編集した場合、もう一方のシートからA列`ind`とB列`task_id`が両方一致する行を探し、対応segmentの同じ列へ値を反映します。N/R列を編集した場合は、編集元を含む両シートで同じ`task_id`を持つ全segmentへ値を反映します。

R列の初期値は空白です。`W` または `d` が入力された行は、Q列が抽出対象でなくても `shell/generate_command_from_spreadsheet.sh` で対応するコマンドへ変換されます。`t` はSpreadsheet上の表示制御にのみ使われ、コマンド生成では他の未対応値と同様に無視されます。そのため、R列が `t` でもQ列が抽出対象なら通常処理されます。同じ `task_id` の複数行でR列の `W` と `d` が混在している場合はエラーになります。

L列の例:

- `実ログ`のA列が`0001`、B列が`abc`の行でL列を編集する
- `優先度低い順`のA列が`0001`、B列が`abc`の行を探す
- 見つかった行のL列へ同じ値を設定する

A列またはB列が空、相手シートに対応するA+Bがない、sourceまたはtargetでA+Bが重複している場合は、同期を開始しません。複数行編集では全対象を先に検証し、異常をシート名・行・identity・理由を含む1回のToastで通知します。

## 貼り付け時の扱い

B列を含む複数行貼り付けは、`shell/copy_for_spreadsheet.sh` の出力を貼り直した操作とみなします。

この場合は同期も復元も行いません。丸ごと貼り直す操作によって、もう一方のシートの値が意図せず変更されることを避けます。

## 同時編集対策

編集時の同期処理では `LockService.getDocumentLock()` を使用します。ロックを取得できない場合、その編集イベントでは同期処理を行いません。

## 注意事項

- segment単位同期は行番号ではなくA+B、task単位同期はB列の`task_id`で行います。
- 対象シート名、同期対象列、データ開始行は `main.js` の `SCHRONU_CONFIG` で管理します。
- Google Apps Script の `onEdit` イベントとして動作するため、最終的な動作確認は Google Sheets 上で行ってください。
