# Apps Script 外部設計

このディレクトリの `main.js` は、Schronu の出力を貼り付けて使う Google Spreadsheet 向けの補助スクリプトです。

## 対象シート

対象シートは以下の2つです。

- `実ログ`
- `優先度低い順`

両シートは、同じタスク集合を異なる順序で表示する用途を想定しています。行番号ではなく、B列の `task_id` をキーにして同一タスクを対応付けます。

## 列仕様

| 列 | 用途 |
| --- | --- |
| B | `task_id`。両シート間の同期キー |
| L | 同期対象 |
| N | 同期対象 |
| P | 同期対象 |
| Q | 抽出対象。`shell/copy_for_spreadsheet.sh` ではP列が手入力のときTRUEになる式を入れる |
| R | 同期対象。初期値は空白、`W`と`d`はコマンド生成指定、`t`はSpreadsheet上の表示制御用 |
| S | 実作業時間。`generate_command_from_spreadsheet.sh`が`働`コマンドの分数へ変換する |

データ行は3行目から始まる前提です。

完全なA-S列の定義はリポジトリルートの`spreadsheet_columns.tsv`を正本とします。A-J列はSchronu出力、K-S列はSpreadsheetの補助列です。

## 業務日境界の睡眠時間

`shell/copy_for_spreadsheet.sh`は06:00を業務日の境界とします。00:00から05:59開始のタスクは前の業務日に属します。入力内で新しい業務日へ移った最初のタスクは、G列の見積もり分数を変更せず、P列の予定完了時刻へ420分を加算し、N列へ`F`を設定します。N列が`F`の行は、Spreadsheetから戻す際に`終`コマンドが生成されません。コピー対象の先頭行と、R列が`W`または`d`の行には加算しません。

## 起動時の動作

Google Sheets を開くと、メニューに `ユーザー関数` が追加されます。

メニュー項目は以下です。

- `時刻形式を再適用`

また、起動時にも時刻形式の再適用を実行します。

## 時刻形式の再適用

`実ログ` と `優先度低い順` の以下の範囲に、時刻表示形式 `hh:mm` を設定します。

- `L3:M500`
- `O3:P500`

対象シートが存在しない場合は、存在しないシート名をアラートで表示します。

## 編集時の同期

`実ログ` または `優先度低い順` の3行目以降で、L/N/P/R列を編集した場合、もう一方のシートから同じ `task_id` の行を探し、同じ列へ値を反映します。

R列の初期値は空白です。`W` または `d` が入力された行は、Q列が抽出対象でなくても `shell/generate_command_from_spreadsheet.sh` で対応するコマンドへ変換されます。`t` はSpreadsheet上の表示制御にのみ使われ、コマンド生成では他の未対応値と同様に無視されます。そのため、R列が `t` でもQ列が抽出対象なら通常処理されます。同じ `task_id` の複数行でR列の `W` と `d` が混在している場合はエラーになります。

例:

- `実ログ` のB列が `abc` の行でL列を編集する
- `優先度低い順` のB列が `abc` の行を探す
- 見つかった行のL列へ同じ値を設定する

相手シートに同じ `task_id` が存在しない場合は何もしません。B列が空の行も対象外です。

## 貼り付け時の扱い

B列を含む複数行貼り付けは、`shell/copy_for_spreadsheet.sh` の出力を貼り直した操作とみなします。

この場合は同期も復元も行いません。丸ごと貼り直す操作によって、もう一方のシートの値が意図せず変更されることを避けます。

## 同時編集対策

編集時の同期処理では `LockService.getDocumentLock()` を使用します。ロックを取得できない場合、その編集イベントでは同期処理を行いません。

## 注意事項

- 同期は行番号ではなくB列の `task_id` で行います。
- 対象シート名、同期対象列、データ開始行は `main.js` の `SCHRONU_CONFIG` で管理します。
- Google Apps Script の `onEdit` イベントとして動作するため、最終的な動作確認は Google Sheets 上で行ってください。
